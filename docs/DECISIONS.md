# 决策记录

本文档记录已经影响仓库结构的决策。新决策向后追加；如果旧决策被替代，标注替代关系，不删除历史。

## D-001：采用单仓库平台边界

- 日期：2026-08-17
- 状态：已接受
- 决策：使用 `apps`、`services`、`packages`、`contracts`、`product` 和 `docs` 表达边界。
- 理由：为多平台计划提供稳定位置，同时不要求当前就拆分复杂模块。

## D-002：探索期不预选未实现平台技术栈

- 日期：2026-08-17
- 状态：已接受
- 决策：Android、iOS、Windows 和后端只创建说明文件，不创建框架脚手架或 Feature 目录。
- 理由：产品需求未完整确定，过早工程化会制造虚假约束。

## D-003：macOS 应用保持完整 SwiftPM 边界

- 日期：2026-08-17
- 状态：已接受
- 决策：将 `Package.swift`、`Sources`、`Tests`、`Resources`、`VERSION` 和 `BUILD_NUMBER` 一起迁入 `apps/macos`。
- 理由：保留已验证的原生应用边界，避免在尚无 iOS 用例时提前抽取共享层。

## D-004：OpenAPI 是未来网络契约的单一源

- 日期：2026-08-17
- 状态：已接受
- 决策：根目录 `contracts/openapi.yaml` 是源文件，`packages/contracts` 只容纳未来派生物或工具。
- 理由：避免源契约与生成代码混杂；当前使用空 `paths` 明确表示 API 需求未确定。

## D-005：使用 `apps/windows` 规范目录名

- 日期：2026-08-17
- 状态：已接受
- 决策：将请求中的 `apps/winodws` 视为拼写错误，建立 `apps/windows`。
- 理由：避免长期固化明显的路径拼写错误。
